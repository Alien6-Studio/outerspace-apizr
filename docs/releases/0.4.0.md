# Apizr 0.4.0

**Core published on PyPI; plugin publication pending.**

Apizr connects selected Python functions to AI agents through MCP or exposes
them as REST APIs. Version 0.4.0 extends that compiler with remote Git sources,
isolated optional plugins and an explicitly authorized delivery workflow.
Python 3.11–3.14 remains supported; the minimal core still depends only on Pydantic.

For installation and first calls, follow [Install Apizr](../getting-started/install.md)
and the [Quickstart](../getting-started/quickstart.md).

## Analyze a project locally or from Git

- Call readiness, planning and REST/MCP generation directly through the
  [Python compiler API](../reference/compiler-api.md), shared with the CLI.
- Use an explicitly selected [apizr.toml](../getting-started/user-guide/project.md)
  for local roots, scan/graph options and policy paths. Explicit CLI options
  take precedence; no project file is loaded automatically.
- Analyze public [HTTPS](../reference/git-sources.md) or private
  [SSH](../reference/git-ssh.md) repositories at a required branch, tag or commit.
  SSH uses an explicitly prepared agent and known-hosts file. A generation keeps
  one acquired snapshot and its resolved commit through analysis and rendering.
- Grant access before source reads through the common
  [operator policy](../reference/operator-policy.md). Fetching Git and analyzing
  its snapshot are separate permissions. Readiness does not grant access or
  select public functions.

## Keep integrations outside the core

Extensions run in separate Python environments and fresh supervised processes.
The core does not import them. [Plugin commands](../reference/local-extensions.md)
support local or HTTPS wheel installation with a required hash, locked local
dependencies, explicit activation/invocation, controlled updates and safe removal
of an inactive, unused version.

[Project declarations and locks](../reference/project-plugin-locks.md) make
installation inputs explicit. A [versioned catalog and profiles](../reference/plugin-catalog.md)
prepare reviewed choices; neither a catalog nor a lock grants permission or
automatically activates a plugin. Artifact integrity does not establish author trust.

| Optional plugin | What it does | Boundary |
| --- | --- | --- |
| [outerspace-apizr-mcp](../reference/apizr-mcp-server.md) | Local stdio analysis, readiness and exposure planning | Captured source scope and operator authority; no Git acquisition, generation or delivery tools |
| [outerspace-apizr-oci](../reference/oci-service-plugin.md) | Build REST/MCP service images and push a verified image to an explicit registry | Immutable image identity, explicit Docker/authentication inputs and independent build/publication grants |
| [outerspace-apizr-attest](../reference/attest-delivery-plugin.md) | Sign, timestamp and verify delivery receipts; [publish, discover and fetch OCI-linked proofs](../reference/attest-oci-artifacts.md) | Independent signing and publication grants; explicit identity, trust and proof digest |

A generated **business MCP server** calls your selected functions.
The **Apizr analysis MCP server** inspects your project and prepares plans.
Installing the core's `mcp` extra does not install or activate `outerspace-apizr-mcp`.

## Compatibility changes to apply

1. Repository `scan`, `graph`, `readiness` and `expose` commands now require
   `--operator-policy` with an exact `source.analyze` grant. Their Python
   filesystem APIs require the same policy. Git commands need `git.fetch` too.
2. Managed image build, signing and publication require their own operator
   grants. Project configuration, exposure selection and plugin activation do
   not grant these rights. See the [operator permissions](../reference/operator-policy.md).
3. Regenerate existing MCP bundles to receive the `structuredContent` fix.
   Non-object returns become an object such as `{"result": 25.0}`; dictionary
   returns are unchanged. REST and Python return values are unchanged. Upgrading
   the compiler alone does not update a previously generated server.

Single-file/notebook `inspect`, `generate rest/mcp`, `execute`, and the historical
YAML pipeline remain supported. Repository analysis stays static. Existing
readiness/exposure contracts, explicit function selection and execution modes
retain their roles; no migration installs plugins or deploys a service automatically.

## Limits and planned follow-up

Plugins and generated services remain trusted code, not sandboxes. Local process
controls do not isolate host files or network access. OCI service images are
different from governed execution worker images. A failed or interrupted transfer
does not prove remote rollback; an unconfirmed remote state is not success.

Git acquisition retains its bounded-process and export restrictions: no checkout,
submodule or LFS materialization, source imports or application dependency
installation. An authorized branch name can move; retain the resolved commit.
A chosen subdirectory does not restrict every Git object transferred.

The following work is explicitly deferred, not included in 0.4.0:

- **0.4.1:** application dependencies/resources, a shared delivery manifest,
  multiple destinations, mandatory proof and Docker Hub/Trunx qualification.
- **0.4.2:** delivery from MCP, Postman export/synchronization, GitHub/GitLab
  integrations, initialization/diagnostics/completion and a Homebrew tap.

See the [tracked delivery scope](../development/0.4.md#delivery-scope-and-explicit-deferrals).
The disposable registry proofs do not qualify third-party registries or establish
catalog admission.

## Publication status

The core `outerspace-apizr==0.4.0` was published on **28 September 2026** from
`37259eaf0a231d747f1ae0eb2f7ce94b2a2b306f` ([qualified CI](https://github.com/Alien6-Studio/outerspace-apizr/actions/runs/36396147495)).
Both public archives were downloaded and matched the approved bytes. A fresh
PyPI installation passed the current Quickstart's MCP and REST calls.

The [publication run](https://github.com/Alien6-Studio/outerspace-apizr/actions/runs/36425349549)
verified the distributions and signed receipt, then published the core. PyPI
refused creation of `apizr-oci`; `apizr-mcp` and `apizr-attest` were not uploaded.
The renamed `outerspace-apizr-*` plugin set is being prepared with a matching
core correction in **0.4.0rc1**; those names do not describe the archives from
that original run. The replacement keeps the same 0.4 documentation and leaves
0.4.1 reserved for functional changes. Its publication remains pending.
The GitHub release remains a draft until coordinated publication is verified.
[Install Apizr](../getting-started/install.md) describes the corrected core and
plugin artifact route. [Publication tracking](https://github.com/Alien6-Studio/outerspace-apizr/issues/180)
records the remaining authorization and delivery checks.

## Official distribution images remain deferred

The CI worker and registry-proof images are disposable test fixtures. They are
not official Apizr images offered for installation. Distribution of official
Apizr images is deferred to subsequent deliveries and remains unfinished; no
public registry destination is claimed. This is separate from the qualified
OCI plugin that builds and publishes a user's service images.
