# Apizr 0.4.4

**0.4.4 is published and verified.** Install it from PyPI or the
[Alien6 Homebrew tap](../getting-started/install.md#homebrew-on-apple-silicon).
The core and optional OCI, MCP and Attest plugins are all available at 0.4.4.

## What you can do with this release

<span id="existing-confirmed-gap-change-expected-evidence"></span>

- **Share a service description** with deployment tools, without running your code.
- **Connect that description to the container you built**, so other tools can
  check they are using the right version.
- **Read delivery results from other languages**, using the provided JSON Schemas.
- **Publish to a new container destination** with improved support for
  authenticated registries.

See [repository exposure and exports](../getting-started/user-guide/exposure.md),
[OCI service images](../reference/oci-service-plugin.md) and
[external governance](../reference/external-governance.md) for the commands and
integration workflow. New to Apizr? Start with the [Quickstart](../getting-started/quickstart.md).

## Upgrade

Follow [Install Apizr](../getting-started/install.md) using version **0.4.4**.
If you use plugins, update the selected profiles to the same version as the core.
Existing generated services have their own runtime dependencies.

<span id="contracts-and-compatibility"></span>

## Compatibility and limitations

Existing v1 schema IDs, serialization and stored results remain compatible.
Export is an additive CLI/Python API and reuses existing bundle documents.
Unknown schemas and fields are refused. A historical build without the required
lineage cannot satisfy the optional bundle-to-build check.

Apizr remains an independent Python tool. Your deployment platform owns
organizational approvals and runtime access control; a successful technical
admission does not replace those decisions.

## Integration status

[Trunx](https://trunx.io/) is a private registry for software packages and
container images. Its integration with Apizr is **still being tested**.
Human approvals have been verified; deployment and access-control checks are
still in progress. Apizr can be used independently of Trunx.

<details markdown="1">
<summary>Integration observations and remaining checks</summary>

The operator reports successful managed installation and delivery/recovery, plus
positive human approvals for MCP A/B in Trunx beta on
`attest-e2e` / `qualification-044`. Full interoperability is not claimed.

Remaining Trunx checks are consumption of immutable image/proof references after
checking authorization, verification of the actual executed result, rejection of
an unapproved version, and enforcement after revocation. Human approval does not
establish those runtime controls. Two immediate REST B rechecks failed with
`admission_failed` then `remote_state_unconfirmed`; later explicit resumes
reportedly completed against the same image/proof without a new build/signature.
The cause remains undetermined. Retain failures and recovery separately; these
observations do not establish a generic Apizr defect.

The ongoing external qualification blocks this release only if it reveals a
blocking defect in Apizr. Any demonstrated generic correction is treated
separately, preserving public v1 contracts and core independence from Trunx.

</details>
