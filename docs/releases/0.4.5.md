# 0.4.5 release candidate

**Not yet published. Finalization is authorized subject to all release gates.** Core, MCP, OCI
and Attest candidate distributions are coordinated at 0.4.5. Published 0.4.4
remains available through the [stable installation guide](../getting-started/install.md).

## For data scientists

Inspect an ordinary notebook without executing it. Record trusted local Runs,
compare their data, code, parameters, environment, metrics and outputs, then
explicitly select a useful prediction capability for REST or MCP. The
[reference quickstart](../getting-started/data-science.md) changes only the active
synthetic dataset between Runs, while preserving the notebook bytes (#259–#267).

The real scientific journey exposed two integration gaps: automatic metrics
under a standard main guard, and the need for exact wheel evidence for external
imports. Wheel evidence records import providers and versions; external code
remains conditional and requires explicit acceptance.

## For Python developers

Private helpers can support selected public functions; unrelated unfinished
research remains visible in the audit without blocking an independent slice.
Structured tuple results and TypedDict inputs share REST/MCP behavior
(#251–#254). MCP analysis has compact summary/detail views (#255), and plugin
preparation retains compatible wheels with their hashes (#256).

## Quality and compatibility

Qualification targets Python 3.11–3.14 on Linux and 3.11/3.14 on macOS, including
the existing installed-package, OCI, Homebrew, security and documentation gates.
The notebook journey was qualified in [#267](https://github.com/Alien6-Studio/outerspace-apizr/issues/267).
Final security remediation is tracked in [#280](https://github.com/Alien6-Studio/outerspace-apizr/issues/280);
MCP distribution and mandatory external verification are tracked in
[#279](https://github.com/Alien6-Studio/outerspace-apizr/issues/279).
Those records retain exact source commits, counts and release evidence.

## MCP discovery and configuration

All six public tools expose trusted human titles, typed input descriptions,
output schemas and reviewed annotations on both supported protocols. Analysis
guidance includes examples and actionable recovery paths. The registry
installation guide explains the three required project, authorization-policy
and plugin-store inputs without silently granting access or enabling delivery.
See the [MCP guide](../reference/apizr-mcp-server.md#registry-installation).

Official Registry publication, Glama indexing, Smithery distribution and
MCPfinder propagation remain pending until the actual public release is verified.
The read-only verifier reports unavailable, missing and stale evidence distinctly.
No third-party score or acceptance is claimed from local qualification.

## Security and reproducibility

Client-collection tooling has a blocking Node dependency audit alongside Python
audits and CodeQL. Reviewed vendor updates preserve Postman, Bruno/OpenCollection
and Insomnia execution. No lifecycle installation scripts or advisory exemptions
are enabled. The explicit 0.4.5 release policy requires protected master, complete
release jobs, signed provenance and retained release assets. Publication must
reuse the original qualified archives and compare all eight public files.

## Boundaries

Inspection does not execute code. Run executes trusted code and is not a sandbox.
Seeds do not establish determinism; comparisons do not establish causality.
Successful Runs and generated services are not production or organizational
approvals. Scientific libraries remain workload dependencies, outside the minimal
core dependency contract. No tracking server, registry or science extra is added.

Release authorization is conditional: any failed mandatory gate stops tagging
and publication. Later documentation records the immutable release source,
workflow runs and actual public provider states without replacing its artifacts.
