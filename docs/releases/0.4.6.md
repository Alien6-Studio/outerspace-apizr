# 0.4.6

Apizr 0.4.6 connects the data-scientist workflow from local Python and Jupyter
experiments to shared Run history, VS Code comparison and explicit REST/MCP
prediction services. Python 3.11–3.15 is supported on the qualified Linux and
macOS targets. Scientific frameworks remain your workload dependencies; the
minimal core still depends only on Pydantic.

## What changes

- Record an explicit Python block with `tracking.session`, or decorate selected
  calls with `tracking.experiment`. Capture bounded parameters, inputs, metrics
  and artifacts while preserving ordinary results and exceptions.
- Use the same sessions in Jupyter, with actual cell IDs, execution counts and
  source digests. Missing or unsaved scientific evidence remains unknown.
- Find and compare the same Runs from CLI, SDK and the VS Code extension. The
  extension uses an explicitly selected installed engine and respects workspace
  trust, read permissions and telemetry controls.
- Expose a successful Run's selected prediction through real REST and MCP
  interfaces, bound to its recorded model and dependencies. Serving does not
  retrain the model; changed artifacts are refused.
- Select scientific recognition providers explicitly. History remains readable
  independently of the producing provider. Telemetry is off by default and has
  no production transmission in this version.
- Use stable uv 0.12.x or 0.13.x for plugin preparation, including native glibc
  2.41 hosts. Homebrew qualification uses Python 3.15 on Apple Silicon.
- Migrate from the retired historical pipeline and Python compatibility facades
  to their canonical owning APIs. The existing notebook exporter and published
  evidence schemas are preserved.

Start with [SDK tracking](../getting-started/tracking.md), the
[ordinary notebook journey](../getting-started/data-science.md), or
[installation](../getting-started/install.md). The
[migration guide](migrate-0.4.6.md) lists the removed entrypoints and store contracts.
